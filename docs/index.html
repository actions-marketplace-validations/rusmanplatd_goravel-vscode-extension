Goravel for VS Code (goravel-vscode)

Rich IDE tooling, Language Server (goravel-lsp), Raw SQL & ORM intelligence, Go HTML Template (.tmpl / .gohtml) support, Workspace Explorers, and Artisan CLI integration for Goravel projects.

Get Started View on GitHub Changelog

Features

Go & Raw SQL Intelligence

TextMate SQL highlighting inside Go strings, schema-aware validation for tables, columns, aliases, CTEs, subqueries, and optional live DB introspection via .env DB_*.

ORM & Framework Intelligence

Model, relationship, config, route (including gRPC), observer, validation rule, and migration indexing, plus facades.View linking to templates.

Goravel Template Support

Syntax highlighting, language configuration, LSP hover with span tracking, detailed type resolution, and snippets for .tmpl and .gohtml files.

Activity Bar Explorer

Browse Models & Schema (with ER Diagram & row preview), Routes (Route Matrix & request tester), Views, Migrations, Commands, Seeders & Schedules.

  • Artisan CLI & Productivity: Explorer context menus for app/models, app/http/controllers, database/migrations, resources/views, and more.
  • Command Palette: Run make:* generators, migrate, migrate:rollback, db:seed, Go tests, and open storage/logs/goravel.log.

Installation

VS Code Extension

Install Goravel (rusmanplatd.goravel-vscode) from the VS Code Marketplace or Open VSX Registry, or install from a .vsix package:

code --install-extension goravel-vscode-1.0.0.vsix

The extension activates automatically when your workspace contains artisan, app/models, or when opening a .tmpl / .gohtml file (requires VS Code ^1.85.0).

Standalone goravel-lsp CLI

Install the standalone goravel-lsp binary using install.sh:

curl -sSfL https://raw.githubusercontent.com/rusmanplatd/goravel-vscode-extension/master/install.sh | sh -s -- -b /usr/local/bin

Or run it directly against a Goravel project:

goravel-lsp --check-sql .
goravel-lsp --check-templates .
goravel-lsp --dump .

Available CLI Flags

FlagDescription
--only-sql / --sql / --check-sqlCheck only SQL and ORM database queries
--only-templates / --templates / --check-templatesCheck only Go HTML templates (.tmpl / .gohtml) and View() variable references
--allRun all diagnostics (SQL, ORM, framework, and templates)
--errors-onlyReport errors only
--sql-source=<auto|model|live-db|both>Schema source: model (Go models/migrations), live-db (.env DB_*), both (merged), auto
--live-dbShorthand for --sql-source=live-db
--out-format=github-actionsFormat output for GitHub Actions annotations
--skip-dirs=dir1,dir2Comma-separated directories to skip

GitHub Action

Use goravel-lsp in CI workflows via action.yml:

- uses: rusmanplatd/goravel-vscode-extension@v1.0.0
  with:
    version: "v1.0.0"        # 'latest', tag (e.g. 'v1.0.0'), or 'master'
    working-directory: "."
    args: "--check-sql"      # or '--check-templates', '--check-sql --check-templates', '--check --all'
    only-sql: "true"
    only-templates: "false"

Examples

1. Raw SQL, Table Variables, CTEs & Scan Struct Validation

goravel-lsp highlights SQL inside Go strings, resolves TableName() variables, validates columns/aliases/CTEs against models and migrations, and checks scan struct fields and placeholders:

userTable := (models.User{}).TableName()
roleTable := (models.Role{}).TableName()

query := `
	WITH active_users AS (
		SELECT u.id, u.email, r.name AS role_name
		FROM ` + userTable + ` u
		LEFT JOIN ` + roleTable + ` r ON r.id = u.role_id
		WHERE u.deleted_at IS NULL
	)
	SELECT id, email, role_name
	FROM active_users
	WHERE email ILIKE $1
`

var rows []UserSummaryRow
err := facades.Orm().Query().Raw(query, "%@example.com").Scan(&rows)

2. ORM Query Builder, Config & Validation Rules

// ORM Query Builder column & relation intelligence
var users []models.User
err := facades.Orm().Query().
	With("Role").
	Where("status = ?", "active").
	OrderBy("created_at", "desc").
	Find(&users)

// Config key completion & go-to-definition (indexes config/*.go)
appName := facades.Config().GetString("app.name")

// Validation rule intelligence in Form Requests (indexes app/rules/*.go)
func (r *CreateUserRequest) Rules(ctx http.Context) map[string]string {
	return map[string]string{
		"email": "required|email|max:255",
		"code":  "required|alpha_dash",
	}
}

3. facades.View & .tmpl / .gohtml Template Intelligence

// In app/http/controllers/user_controller.go
return ctx.Response().View().Make("users/index.tmpl", map[string]any{
	"title": "Users",
	"users": users,
})
<!-- In resources/views/users/index.tmpl -->
{{ define "users/index.tmpl" }}
  {{ template "layouts/header.tmpl" . }}
  <h1>{{ .title }}</h1>
  <ul>
    {{ range $index, $user := .users }}
      <li>{{ $user.Email }}</li>
    {{ end }}
  </ul>
{{ end }}

4. Built-in Code Snippets

  • Go (snippets/goravel.code-snippets): gctrl (Controller), greq (Form Request), gmodel (ORM Model)
  • Templates (snippets/goravel-tmpl.code-snippets): gdefine, gtemplate, gblock, gif, gifelse, grange

5. goravel-lsp CLI Usage

# Print indexed tables, columns, relations, routes, configs, rules, and migrations
goravel-lsp --dump .

# Check only SQL and ORM queries (using Go models & migrations)
goravel-lsp --check-sql --sql-source=model .

# Check SQL queries against live database introspection (.env DB_* settings)
goravel-lsp --check-sql --sql-source=live-db .

# Check only Go HTML template variables, syntax, includes, and View() calls
goravel-lsp --check-templates .

# Check everything (SQL, ORM, routes, configs, views, templates) and report errors only
goravel-lsp check --all --errors-only .

6. GitHub Actions CI Workflow

name: Goravel SQL & ORM Lint

on:
  push:
    branches: [main, master]
  pull_request:

jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: rusmanplatd/goravel-vscode-extension@v1.0.0
        with:
          version: "v1.0.0"
          working-directory: "."
          args: "--check-sql --errors-only --sql-source=model"
          only-sql: "true"

Extension Settings

SettingDefaultDescription
goravel.server.path""Path to the goravel-lsp binary. Defaults to the bundled bin/goravel-lsp.
goravel.sql.enabletrueEnable Goravel Raw SQL and Framework intelligence inside Go files.
goravel.sql.liveIntrospectionfalseEnable optional live database schema introspection using .env DB_* settings.
goravel.sql.source"auto"Schema source: "auto", "model", "live-db", or "both".
goravel.artisan.command"go run . artisan"Base Artisan CLI command prefix (e.g. go run . artisan, ./artisan, or Docker).

npm run package           # Package .vsix into dist/
